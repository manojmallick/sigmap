# Call-graph accuracy

`--callers`, `--callees` and `get_method_impact` answer from SigMap's method-level call graph (`src/graph/call-graph.js`). The docs called its answer a lower bound and named the scope searched; they did not say how much of the truth that bound is. This page measures it against an independent reference.

The reference is a [SCIP](https://github.com/scip-code/scip) index of the same code, written by the language's own indexer (the TypeScript checker for TypeScript and JavaScript, Pyright for Python, the Go type checker, `javac` for Java). Every reference occurrence of a function, method or class is mapped to the function that contains it, which gives caller-to-callee edges that the graph's regular-expression-and-brace matching never touched. Call it **compiler-derived**, not ground truth: a compiler cannot resolve a call through an untyped value, so the reference misses some real edges, and **the precision below is a lower bound**.

The method, the repositories and the pass/fail threshold were written down and committed before the scorer ran on any of them ([`benchmarks/CALLGRAPH_ACCURACY_PROTOCOL.md`](https://github.com/manojmallick/sigmap/blob/main/benchmarks/CALLGRAPH_ACCURACY_PROTOCOL.md)). Everything after the first run is logged in that file's deviation log, with the first run's figures kept. The full numbers, and the first misses of every repository, are in [`benchmarks/reports/callgraph-accuracy.json`](https://github.com/manojmallick/sigmap/blob/main/benchmarks/reports/callgraph-accuracy.json).

## What the figures say

- **A call through a receiver is not in the graph, except in Java.** `this.save()`, `self.save()` and `repo.save()` have no edge: 0.0% of 664 reference edges in TypeScript, 0.1% of 23,863 in Python, 0.0% of 1,883 in Go. The graph resolves `.name(` calls through a declared type only for Java (`buildTypeMap` is built only for `.java` files, and `callsInRange` skips a `.name(` access). In Java, on the one repository that built, it finds 43.8% of 178. The threshold registered before the run was 70%, so by the protocol's own rule a receiver-type pass is warranted in TypeScript, Python, Go and Java. JavaScript is not testable: its two repositories give only 2 such edges, because express assigns most of its functions to properties (`app.use = function use() {}`), which the compiler index does not name.
- **Plain calls `f()` are found well where the graph has the nodes and can follow the import.** Go: 99.0% of 1,186. JavaScript: 99.3% of 135, almost all fastify's. Python is lower at 55.7% of 9,447, and 3,920 of its 4,185 misses are a call to a function in another file that the graph did not link to its definition. TypeScript is lowest at 26.5% of 309, and 187 of its 227 misses involve a function the graph has no node for. A one-off check of the 111 distinct callee functions without a node in zod and excalidraw found 106 are generic declarations, `function pointFrom<P extends Point>(…)`: the graph's function pattern requires `(` right after the name. The other 5 are method signatures declared without a body. Calls hidden inside a template literal (`` `${f()}` ``) are a real blind spot too, but they account for only 5 of those 227.
- **Classes are not nodes.** `new Repo()` and `Repo()` are not edges: constructor recall is 0.0% in TypeScript (178 edges) and Python (17,014). Go has 31 such edges and Java 27, too few to quote (Go found none, Java 7.4%).
- **When the graph does draw an edge, it is right in Go and Java and mostly right in Python.** Precision is 98.9% in Go and 98.1% in Java (one repository). In Python it is 69.3%, and 2,026 of its 2,496 wrong edges (81%) are an edge to a function declared inside the caller: the nested `def decorator(f):` line is read as a call to `decorator`. Without those, Python precision would be 92.3%. flask's 7.6% is its test suite for the same reason: 555 of its 558 wrong edges are the local `def index():` views its tests define.
- **For TypeScript and JavaScript, most of the graph's edges cannot be judged.** 1,278 of the 1,365 TypeScript graph edges have a caller or callee that is a function-local constant (`const onClick = () => …` inside a React component), which scip-typescript gives no callable identity, so they are counted as wrong by the registered definition and are not shown to be. The 87 edges both sides can name are right 94.3% of the time, a cell too small to quote. The registered precision stays the headline; the judgeable column says how much of it is the reference's blind spot.
- **The graph reads fewer files than the index covers.** The scope table has the counts, and recall counted over every reference edge, including files the graph never walked, is lower still: 5.3% in TypeScript, 10.7% in Python, 36.2% in Go.

## What this does not say

- Nothing about PHP, C#, C/C++, Swift, Dart, Lua, GDScript, Vue, Svelte or Astro: the graph reads none of them ([#979](https://github.com/manojmallick/sigmap/issues/979)). Nor about Rust, Kotlin, Scala or Ruby, where no SCIP indexer was run.
- **Java is one repository** (spring-petclinic). gson did not build under scip-java: its `pom.xml` passes Error Prone to `javac`, scip-java's compiler wrapper rejects it, and removing it led to further build checks. It is reported unmeasured with the error, not replaced.
- Two or three repositories per language is a small sample. The brackets are over caller files within those repositories, not over repositories, and a monorepo or a generated-code-heavy repository may score differently. express contributes 3 reference edges to the JavaScript row.
- Dependencies are not installed in the measured copy, so a call whose receiver type comes from an installed package is unresolved by the indexer. JSX element references count as non-calls on both sides.
- The reference cannot see function-local constants, class fields assigned a function, or calls through an untyped value; it is a lower bound on the real edges as well as on the graph's precision.
- A git co-change reference (files that change together) was considered and is not included: the pinned clones are single-commit checkouts.

## Reproduce

```bash
node scripts/fetch-xrepo-repos.mjs --only zod,excalidraw,express,fastify,flask,fastapi,django,gin,gorm,gson
node scripts/run-callgraph-accuracy.mjs --setup-indexers <dir> --with go,java
node scripts/run-callgraph-accuracy.mjs --indexers <dir>              # prints the tables
node scripts/run-callgraph-accuracy.mjs --indexers <dir> --save       # also writes the report
node scripts/run-callgraph-accuracy.mjs --write-doc                   # re-renders the tables above from the report
```

Each repository is exported at its pinned commit with `git archive` into a scratch directory, so the clones under `benchmarks/repos` are only read. Indexers and toolchains are installed into `<dir>`, never system-wide, and every download is checked against a published checksum. `--save` refuses a partial run, a protocol that differs from the committed one, and a dirty scored tree. The harness is dev-only: nothing here ships in the npm package, and nothing at runtime depends on an indexer.
