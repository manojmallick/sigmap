# Import-graph accuracy

`--impact`, `get_impact`, the blast radius in `plan` and the counts in `sigmap doctor` answer from SigMap's import graph (`src/graph/builder.js`). Until #980 it read eight language families; it now reads fifteen (C/C++/Objective-C, PHP, C#, Dart, Vue/Svelte/Astro, Lua and GDScript were added) and gives a module-level answer for Swift. This page measures how far the **edges** it draws agree with what each language's own tooling resolves.

The reference is never SigMap's own resolver. It is the compiler or the framework's parser: `clang -E -H` for C and C++, TypeScript's module resolution behind the Vue, Svelte and Astro parsers for components, PHP's tokenizer and Composer's autoloader for PHP, and the Swift compiler with SwiftPM for Swift. Call it **compiler-derived**, not ground truth: a reference reports the configuration it ran, and an import that depends on another configuration is not in it.

The method, the repositories, the predictions and the thresholds were written down and committed before the scorer ran on any of them ([`benchmarks/IMPORT_RESOLVER_PROTOCOL.md`](https://github.com/manojmallick/sigmap/blob/main/benchmarks/IMPORT_RESOLVER_PROTOCOL.md)). The deviation log in that file records everything that happened after the first run, with the first run's figures kept. The full numbers, and the first disagreements of every repository, are in [`benchmarks/reports/import-accuracy.json`](https://github.com/manojmallick/sigmap/blob/main/benchmarks/reports/import-accuracy.json).

## How to read them

**Precision** is the share of the graph's edges that the reference also has. **Recall** is the share of the reference's edges that the graph has. Both are over the importing files that the graph walked **and** the reference could analyse, so a file the reference could not parse is out of both counts and shows in the scope table as walked but not scored (svelte's deliberately invalid compiler-error samples are of this kind). The graph's walk is the zero-config one a user gets.

**C, C++ and Objective-C.** The two agree on almost every include. The extra edges are includes behind a platform switch (`unix.h` including `aix.h`, `os390.h`, `sunos.h`): the reference ran the host, Linux and Windows, and an include behind another switch is not in it, so the precision is a lower bound. The missed edges are all `.inc` files, which the graph does not treat as source files (abseil uses them for per-platform fragments).

**PHP.** The two agree on every `use` of a class in laravel and composer. The one extra edge is a literal `require` of a file, which the reference does not read, so PHP precision is also a lower bound.

**Swift is module level.** A Swift file imports a module, not a file, so the graph draws no file-to-file edge for Swift and the reference edge is "this file imports that target of the package". `--impact` on a Swift file names its target and lists the files in other targets that import it. The one miss is a C-language target of vapor, which has no Swift file to ask about.

**Components, and the prediction that was missed.** Every edge the graph draws between components is one the reference has (precision above), but component recall is the lowest of the four groups. The registered prediction was 90% recall; it was **missed**. None of the remaining causes is in the component reader (two defects there were found by this benchmark and fixed, and are in the deviation log): the script found in a `.vue`, `.svelte` or `.astro` file goes through the same specifier resolution as a `.ts` file, and that resolver does not read

- the package's own name, resolved through the `exports` field of its own `package.json` (every file of the `svelte` package that imports `svelte` reaches `types/index.d.ts`; all of the "bare specifier" misses are in that one repository);
- a specifier written `./x.js` for a file `x.ts`, or `./x.jsx` for `x.tsx`, which is how TypeScript projects write imports under Node's rules;
- a JSON module, and a `#name` import of the `imports` map;
- an extension-less specifier that reaches a `.d.ts` file.

The registered guess named bundler aliases and `.js`-to-`.ts` mappings; the second is real (a dozen edges, all in astro), but the larger cause is the package naming itself, in svelte. These are real gaps for every `.js` and `.ts` file too, which this benchmark does not measure. They are **not** fixed here: that resolver also builds the graph the ranker reads, so widening it moves retrieval (#934) and needs its own review against the retrieval gate. A list of imports that spans several lines is read in a component's script and, for the same reason, is *not* read in a plain `.js` or `.ts` file.

**Not measured.** C#, Dart, Lua and GDScript have resolvers and test fixtures with known answers, but no figure. A C# or Dart reference is a compiler front end that needs an SDK, a restore and a build of the repository; Lua finds a module through a path the project sets at run time; and GDScript is resolved by the engine. A number from a weaker oracle would be a number about the oracle, so there is none.

## What the figures do and do not say

- They say how often the graph's edges agree with what each language's tooling resolves, for these repositories, over the files both read. They are not a statement about every repository, and a repository's own build configuration (a `-D` switch, a bundler alias table) can change what its tooling resolves.
- A cell with fewer than 100 edges is shown and not quoted; the intervals are 95% cluster-bootstrap intervals over importing files.
- Precision says nothing about completeness and recall says nothing about the extra edges; read the two together, and read each against the reference's own limits above.
- The ranker's neighbour boost still reads only the original eight families. These figures are about the blast-radius surfaces, not about retrieval.

## Reproduce

```bash
node scripts/fetch-xrepo-repos.mjs --only libuv,abseil-cpp,vue-core,svelte,astro,laravel,composer,alamofire,vapor
node scripts/run-import-accuracy.mjs --setup-references /path/to/refs     # pinned TypeScript, the framework parsers, PHP and Composer
node scripts/run-import-accuracy.mjs --references /path/to/refs            # prints the tables
node scripts/run-import-accuracy.mjs --references /path/to/refs --save    # also writes benchmarks/reports/import-accuracy.json
node scripts/run-import-accuracy.mjs --write-doc                          # re-renders the tables above from the saved report
```

C and Swift need `clang` and `swift` on the path. Each repository is exported at its pinned commit into a scratch directory, so the shared clones are only read. `--save` refuses a partial run, a protocol that differs from the committed one, and a scored tree with uncommitted changes.
